1Ringkasan pendekatan

Tiga tabel inti: profiles (akun pengguna & admin), permohonan (siklus hidup permohonan informasi beserta SLA), dan konten_landing (konten dinamis landing page). Semua tabel diproteksi Row Level Security sehingga isolasi data antar pengguna terjadi di level database, bukan hanya di kode aplikasi — jadi tetap aman meski ada bug di frontend.

Perhitungan tenggat waktu (SLA 10 hari kerja + opsi perpanjangan 7 hari kerja) dilakukan otomatis lewat trigger database, bukan di kode Next.js, supaya konsisten di semua jalur insert/update — termasuk kalau suatu saat ada import data manual.

2Tabel profiles

Menyimpan data pengguna publik maupun admin. id sengaja disamakan dengan auth.users.id bawaan Supabase Auth, bukan id baru — supaya tidak perlu tabel mapping terpisah.

create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  nama text not null,
  nik text not null check (nik ~ '^[0-9]{16}$'),
  email text,
  telepon text,
  role text not null default 'pemohon'
    check (role in ('pemohon', 'admin')),
  created_at timestamptz not null default now()
);

Catatan: karena admin hanya satu akun shared, cukup 1 baris dengan role = 'admin' — tidak perlu tabel role terpisah.

3Tabel permohonan

create table public.permohonan (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.profiles(id) on delete cascade,
  jenis_informasi text not null,
  deskripsi text not null,
  cara_memperoleh text not null,
  status text not null default 'diajukan'
    check (status in ('diajukan', 'diproses', 'dijawab', 'ditolak')),
  jawaban_admin text,
  deadline_awal date,
  diperpanjang boolean not null default false,
  alasan_perpanjangan text,
  deadline_akhir date,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

deadline_awal dan deadline_akhir diisi otomatis oleh trigger (lihat bagian 7), tidak diisi manual dari aplikasi.

4Tabel konten_landing

create table public.konten_landing (
  id uuid primary key default gen_random_uuid(),
  section_key text not null
    check (section_key in ('berkala', 'serta_merta', 'setiap_saat', 'dikecualikan')),
  judul text not null,
  isi_teks text,
  link_drive text,
  updated_by uuid references public.profiles(id),
  updated_at timestamptz not null default now()
);

5Row Level Security

Aktifkan RLS di ketiga tabel sebelum menulis policy apa pun. Tanpa enable row level security, policy tidak akan berlaku dan tabel tetap terbuka penuh. 
alter table public.profiles enable row level security;
alter table public.permohonan enable row level security;
alter table public.konten_landing enable row level security;

-- profiles: user hanya baca/edit datanya sendiri
create policy "user lihat profil sendiri" on public.profiles
  for select using (auth.uid() = id);

create policy "user edit profil sendiri" on public.profiles
  for update using (auth.uid() = id);

-- permohonan: user hanya kelola miliknya sendiri
create policy "user lihat permohonan sendiri" on public.permohonan
  for select using (auth.uid() = user_id);

create policy "user insert permohonan sendiri" on public.permohonan
  for insert with check (auth.uid() = user_id);

-- permohonan: admin akses penuh
create policy "admin lihat semua permohonan" on public.permohonan
  for select using (
    exists (
      select 1 from public.profiles
      where id = auth.uid() and role = 'admin'
    )
  );

create policy "admin update semua permohonan" on public.permohonan
  for update using (
    exists (
      select 1 from public.profiles
      where id = auth.uid() and role = 'admin'
    )
  );

-- konten_landing: publik boleh baca tanpa login, hanya admin boleh tulis
create policy "publik baca konten landing" on public.konten_landing
  for select using (true);

create policy "admin insert konten landing" on public.konten_landing
  for insert with check (
    exists (
      select 1 from public.profiles
      where id = auth.uid() and role = 'admin'
    )
  );

create policy "admin update konten landing" on public.konten_landing
  for update using (
    exists (
      select 1 from public.profiles
      where id = auth.uid() and role = 'admin'
    )
  );

create policy "admin hapus konten landing" on public.konten_landing
  for delete using (
    exists (
      select 1 from public.profiles
      where id = auth.uid() and role = 'admin'
    )
  );

6Fungsi penghitung hari kerja

Fungsi bantu untuk menambahkan N hari kerja (melewati Sabtu & Minggu) dari tanggal tertentu. Dipakai oleh trigger di bagian 7.

create or replace function public.add_business_days(start_date date, jumlah_hari int)
returns date
language plpgsql
immutable
as $$
declare
  hasil date := start_date;
  terhitung int := 0;
begin
  while terhitung < jumlah_hari loop
    hasil := hasil + 1;
    if extract(dow from hasil) not in (0, 6) then
      terhitung := terhitung + 1;
    end if;
  end loop;
  return hasil;
end;
$$;

opsional Kalau nanti mau lebih presisi, fungsi ini bisa dikembangkan untuk mengecualikan hari libur nasional juga (perlu tabel hari_libur terpisah) — versi ini cukup untuk kebutuhan awal.

7Trigger otomatisasi

7.1 Set deadline awal saat permohonan dibuat

create or replace function public.set_deadline_awal()
returns trigger
language plpgsql
as $$
begin
  new.deadline_awal := public.add_business_days(current_date, 10);
  return new;
end;
$$;

create trigger trg_set_deadline_awal
before insert on public.permohonan
for each row execute function public.set_deadline_awal();

7.2 Set deadline akhir saat admin mengaktifkan perpanjangan

create or replace function public.set_deadline_akhir()
returns trigger
language plpgsql
as $$
begin
  if new.diperpanjang = true
     and (old.diperpanjang is distinct from true) then
    new.deadline_akhir := public.add_business_days(new.deadline_awal, 7);
  end if;
  return new;
end;
$$;

create trigger trg_set_deadline_akhir
before update on public.permohonan
for each row execute function public.set_deadline_akhir();

7.3 Auto-update kolom updated_at

create or replace function public.set_updated_at()
returns trigger
language plpgsql
as $$
begin
  new.updated_at := now();
  return new;
end;
$$;

create trigger trg_permohonan_updated_at
before update on public.permohonan
for each row execute function public.set_updated_at();

8Auto-provisioning profil saat registrasi

Saat user mendaftar lewat Supabase Auth, baris di profiles dibuat otomatis lewat trigger di tabel auth.users — data nama & NIK dikirim lewat metadata saat signup.

create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = public
as $$
begin
  insert into public.profiles (id, nama, nik, email)
  values (
    new.id,
    new.raw_user_meta_data ->> 'nama',
    new.raw_user_meta_data ->> 'nik',
    new.email
  );
  return new;
end;
$$;

create trigger on_auth_user_created
after insert on auth.users
for each row execute function public.handle_new_user();

Di sisi Next.js, saat memanggil supabase.auth.signUp(), sertakan options.data berisi { nama, nik } supaya trigger ini bisa mengisi kolomnya.

10Integrasi notifikasi Telegram

Pendekatan: gunakan fitur Database Webhooks Supabase (berbasis ekstensi pg_net), yang otomatis memanggil sebuah Edge Function setiap ada baris baru di permohonan. Tidak perlu polling atau cron.

10.1 Edge Function pengirim notifikasi

supabase/functions/notify-telegram/index.ts 
import { serve } from "https://deno.land/std/http/server.ts";

serve(async (req) => {
  const payload = await req.json();
  const permohonan = payload.record;

  const pesan =
    "Permohonan informasi baru\n" +
    "Jenis: " + permohonan.jenis_informasi + "\n" +
    "Deskripsi: " + permohonan.deskripsi + "\n" +
    "Batas jawab: " + permohonan.deadline_awal;

  const token = Deno.env.get("TELEGRAM_BOT_TOKEN");
  const chatId = Deno.env.get("TELEGRAM_CHAT_ID");

  const res = await fetch(
    "https://api.telegram.org/bot" + token + "/sendMessage",
    {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ chat_id: chatId, text: pesan }),
    }
  );

  if (!res.ok) {
    console.error("Gagal kirim notifikasi Telegram", await res.text());
  }

  return new Response("ok");
});

10.2 Setup webhook di Supabase

  1. Deploy fungsi: supabase functions deploy notify-telegram
  2. Set secret: supabase secrets set TELEGRAM_BOT_TOKEN=xxx TELEGRAM_CHAT_ID=xxx
  3. Di dashboard Supabase > Database > Webhooks, buat webhook baru: tabel permohonan, event INSERT, target Edge Function notify-telegram.
Kegagalan pengiriman notifikasi (mis. Telegram API down) tidak akan membatalkan penyimpanan permohonan — webhook berjalan setelah insert berhasil, jadi data pemohon tetap aman. Cukup pastikan error-nya ter-log (lewat console.error di atas, terlihat di Supabase > Edge Functions > Logs) supaya bisa dipantau.

11Checklist deployment

  • Jalankan seluruh DDL (bagian 2-4) dalam satu migration file agar urutan pembuatan tabel & foreign key konsisten.
  • Aktifkan RLS dan pastikan setiap tabel punya minimal satu policy select — tabel dengan RLS aktif tapi tanpa policy akan menolak semua akses, termasuk dari service role bila salah setting.
  • Uji trigger set_deadline_awal dengan insert data dummy, cek hasil deadline_awal sudah melewati akhir pekan dengan benar.
  • Buat 1 baris admin manual di profiles (lewat SQL editor Supabase, bukan lewat form signup publik) untuk akun admin shared.
  • Test end-to-end: submit permohonan dari akun pemohon dummy → pastikan notifikasi Telegram masuk dalam hitungan detik.
Dokumen ini melengkapi PRD Sistem PPID Digital v1.0. Perubahan skema di masa mendatang sebaiknya dicatat sebagai migration file bernomor urut, bukan mengedit tabel langsung dari dashboard Supabase.
