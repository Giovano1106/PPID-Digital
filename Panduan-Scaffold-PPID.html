3Environment variables

.env.local 
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxx
SUPABASE_SERVICE_ROLE_KEY=xxxxxxxxxxxxxxxx
SUPABASE_SERVICE_ROLE_KEY melewati semua RLS policy — jangan pernah dipakai di client component atau dikirim ke browser. Hanya untuk server action/route handler yang memang butuh akses penuh (jarang dibutuhkan di proyek ini karena RLS sudah menangani sebagian besar kasus).

Nilai NEXT_PUBLIC_SUPABASE_URL dan ANON_KEY diambil dari Supabase Dashboard > Project Settings > API.

lib/supabase/server.ts 
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'

export async function createClient() {
  const cookieStore = await cookies()

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll()
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value, options }) =>
            cookieStore.set(name, value, options)
          )
        },
      },
    }
  )
}

5Middleware proteksi route

Melindungi /permohonan-saya/* (wajib login) dan /admin/* (wajib role admin) sebelum halaman dirender.

middleware.ts 
import { createServerClient } from '@supabase/ssr'
import { NextResponse, type NextRequest } from 'next/server'

export async function middleware(request: NextRequest) {
  let response = NextResponse.next({ request })

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll()
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value)
          )
          response = NextResponse.next({ request })
          cookiesToSet.forEach(({ name, value, options }) =>
            response.cookies.set(name, value, options)
          )
        },
      },
    }
  )

  const { data: { user } } = await supabase.auth.getUser()
  const path = request.nextUrl.pathname

  if (!user && path.startsWith('/permohonan-saya')) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  if (path.startsWith('/admin')) {
    if (!user) return NextResponse.redirect(new URL('/login', request.url))

    const { data: profile } = await supabase
      .from('profiles')
      .select('role')
      .eq('id', user.id)
      .single()

    if (profile?.role !== 'admin') {
      return NextResponse.redirect(new URL('/', request.url))
    }
  }

  return response
}

export const config = {
  matcher: ['/permohonan-saya/:path*', '/admin/:path*'],
}

6Skeleton halaman per fitur

Urutan file yang perlu dibuat, dari yang paling sederhana:

  1. app/(public)/page.tsx — landing page, fetch konten_landing tanpa auth
  2. app/(auth)/daftar/page.tsx — form nama, NIK, email, telepon, password → supabase.auth.signUp() dengan metadata { nama, nik }
  3. app/(auth)/login/page.tsx — supabase.auth.signInWithPassword()
  4. app/permohonan-saya/ajukan/page.tsx — form insert ke tabel permohonan
  5. app/permohonan-saya/page.tsx — list query permohonan milik user, tampilkan badge status + sisa SLA
  6. app/admin/page.tsx — list semua permohonan (RLS otomatis izinkan karena role admin)
  7. app/admin/permohonan/[id]/page.tsx — detail + form update status & jawaban
  8. app/admin/konten/page.tsx — CRUD konten_landing

7Setup migrasi database

npx supabase login
npx supabase link --project-ref xxxxxxxxxxxx
npx supabase db push

Taruh seluruh DDL dari dokumen TDD (tabel, RLS, trigger) ke supabase/migrations/0001_init.sql sebelum menjalankan db push, supaya histori perubahan skema tetap tercatat di Git.

8Deploy ke Vercel

  1. Push proyek ke GitHub.
  2. Buka vercel.com/new, import repository.
  3. Tambahkan tiga environment variable dari bagian 3 di pengaturan project Vercel.
  4. Deploy — Vercel otomatis build ulang setiap ada push ke branch utama.

Untuk Edge Function Telegram, deploy terpisah lewat Supabase CLI (supabase functions deploy notify-telegram) seperti sudah dijelaskan di dokumen TDD — ini tidak ikut proses deploy Vercel karena jalan di sisi Supabase.

9Urutan pengerjaan disarankan

  1. Jalankan migrasi database (bagian 7) sampai tabel & RLS aktif di Supabase.
  2. Setup koneksi Supabase di Next.js (bagian 4) dan pastikan bisa fetch data dummy.
  3. Bangun alur auth (daftar, login, middleware) sampai bisa bedakan sesi pemohon vs admin.
  4. Bangun landing page publik — paling cepat terlihat progresnya, bagus untuk demo awal.
  5. Bangun form pengajuan & halaman riwayat pemohon.
  6. Bangun dashboard admin, lalu sambungkan Edge Function Telegram terakhir setelah alur insert permohonan stabil.
